# 过程动画模式（Process Animation）

不只展示「是什么」，更要展示「怎么算」。让观众亲眼看到数据流动和计算发生。

## 适用场景

| 场景 | 说明 |
|------|------|
| 算法可视化 | 排序、搜索、图遍历 |
| 数学公式推导 | 矩阵乘法、卷积运算 |
| 数据处理流程 | CNN 前向传播、数据清洗 |
| 决策过程 | 池化取最大值、softmax |

## 组件库

### StepByStepCalc - 逐步计算展示

接收 `steps: string[]`（如 `["1×0.5", "+ 0×0.3", "= 0.3"]`），用 `startFrame` 和 `framesPerStep` 控制逐步显示，最后一步高亮为结果色。

### ValueFlyIn - 数值飞入

计算结果从 `from` 位置飞到 `to` 位置，用 spring 控制轨迹，飞行时放大、落地缩小。

### CompareHighlight - 区域比较

多值依次比较，当前比较项高亮，最终胜出者（最大值）持久高亮。用于池化等操作。

### SlidingWindow - 滑动窗口

卷积核/池化窗口在网格上滑动。输入 `gridSize`、`windowSize`、`stride`、`currentStep`，自动计算窗口位置。

// 所有组件的共同模式：

## 脚本撰写

**关键**：脚本必须给动画「留白时间」。

❌ 传统：一句话带过整个过程
✅ 过程式：每步对应一句 + 停顿

```
"让我们看看卷积是怎么计算的。"（停顿 - 窗口移动）
"卷积核覆盖了这 9 个像素。"（停顿 - 高亮区域）
"我们把每个像素值和权重相乘..."（停顿 - 逐步乘法）
"然后加起来。"（停顿 - 求和）
"这个数字写入特征图。"（停顿 - 结果飞入）
"接下来窗口向右滑..."（加速后续步骤）
```

## 时间分配

| 详细程度 | 首次完整展示 | 重复加速 | 适用 |
|----------|------------|---------|------|
| 极详细 | 3-4s/步 | 0.5s/步 | 核心概念首次出现 |
| 中等 | 2s/步 | 0.3s/步 | 辅助概念 |
| 快速 | 1s/步 | 闪过 | 已解释过的重复 |

## 踩坑经验

| 问题 | 解决方案 |
|------|----------|
| 动画太快看不清 | 增加关键步骤帧数 |
| 解说与动画不同步 | 重写脚本加停顿标记 |
| 信息过载 | 分阶段：先结构再过程 |
| 重复内容无聊 | 首次详细 + 后续加速 |
| 相机持续抖动 | 直接设置位置或用 spring，不要用 `pos += (target-pos)*factor` |
| 网格图像旋转90度 | col→x, row→y(翻转)：`y = ((size-1-row) - size/2 + 0.5) * cellSize` |
| 进度显示好几千% | `Math.min(1, (frame - start) / duration)` 必须 clamp |
