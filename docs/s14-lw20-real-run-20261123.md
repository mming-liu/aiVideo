## 处理意见（2026-11-23 按复核修订）

已确认：59/74 次修订是空 `edits`；第 1 章 14/20 首答满足的是总条数与总字数，这 14 轮仍全部进入局部替换。
源码里有两处矛盾：提示允许返回空数组而应用端必拒；合法但未清完的修订，下一轮仍从原稿开始。
**空答的动机未证实**，下列修法须用冻结材料验证，不按"去掉出口模型就会配合"推定。

1. **不追加 20 轮实跑。** 两项规划修复通过冻结回放后，再按原范围确认两章各一轮。
2. **修订协议（离线，限 40 份冻结材料）：** 第一轮有实质进展即保存到临时副本，第二轮只处理残余，
   最终全验通过才交分镜。删声后 `D/N` 序号前移，两轮之间按原事件/节拍/声音身份映射。候选先按完整语意、
   说话人和证据筛选再缩量；无保真选项时给出明确的不可修原因。**不**简单要求"每个可编辑 ID 都改一次"——
   `trim` 把全部声音列为可编辑，达标往往只需改几句。验收看第二轮实际请求与最终播出序列；
   第 1 章用 4 次合法部分修订验证。
3. **第 2 章先修证据取用，不改产品口径：** 对 11 条逐一核对绑定事实、原文位置、候选播出文本和 12s 上限，
   从已绑定证据提出候选，再核观众能否得到完整主张。`ch2_r01` 为首个成功路径验证对象。证据确实覆盖不了的
   轮次列出具体丢失哪一层主张；那时若仍须改必保事实或分集，再提交内容裁决。原第 3 条"删背景/拆集/放宽对白"
   的选择题撤回。
4. **分镜时长独立处理：** 分镜提示已写正片 60–90s、规划目标和按镜数反推平均时长，不再追加同义要求。
   用上表 5 份原答逐镜对齐申报时长、发声与动作下限、后处理增量，找出生成前可识别的超配，以及后处理
   中无依据的增量。保留 90s 上限和 300/1200s 预算。
5. 基础设施失败（1 次 SSL）按调用失败处置，不计入修法评估。
