## 2. P02 顺序契约与引用投影

**判据**（`step01_script_gen/plan_feasibility.py`）：

- `voice_order_records(plan)`：承载次序**唯一**且与 `dialogue_lines` 数组序不一致时，
  返回 `voice_order_conflict`（含 D 身份、承载节拍、字段路径、冲突关系）。
- `apply_voice_order_projection(plan)`：唯一可确定时，统一重排 `dialogue_lines`，并同步
  节拍「载体：台词k」、事实「承载：…/台词k」、`hook_carrier`、`voice_adaptations.entries[].index`、
  `presentation.dialogue_uids`；只改编号与引用，不改文本/说话人/主张/节拍正文。
- **适用边界**：孤儿、悬空、非法载体、**多重承载**一律不自动排序，也不因"多重承载"
  新增拒收（顺序不唯一时保留原计划）；`changed=False` 时幂等。
- 计划身份：投影会改变 `plan_identity` 与 `plan_digest_of`，旧核验记录随之作废。

**生产接线**（`step01_script_gen/outline.py`）：

| 入口 | 位置 | 行为 |
|---|---|---|
| 首版/修订统一入口 | `run_plan_revision`（规范化之后、`attach_verification` 之前） | 投影后摘旧记录，按新摘要核验 |
| 视图候选定稿 | `complete_candidate`（投影之后、挂核验之前） | 同上 |
| 旧 ops/整稿候选 | `revise_plan_once` 候选定稿与预算重选路径 | 同上 |
| 旧缓存装载 | `generate_outline_result` 缓存分支 | 投影后摘旧记录；若剩余问题只有 `verify_record_missing`，缓存作**待核验候选**复用并重新核验 |
| 生成前门 | `plan_contract_records` → `check_plan_before_generation` | 未投影的矛盾计划在生成前报 `voice_order_conflict` |

**用例**：`tests/step01_script_gen/test_plan_voice_order.py`（15 passed）——冲突识别、
契约记录、合法序、无承载契约、多重承载、孤儿、悬空、引用重映射、幂等、跨内容参数化、
`complete_candidate` 与 `run_plan_revision` 的"先投影再挂核验"接线。

## 3. P03 固定稿修复入口

`tools/replay_step01_repair.py`：

- `--input-manifest` 覆盖原文、小说身份、部/章范围、计划、稿件、问题集、预算、通道；
  隔离根/台账/日志在**导入项目配置之前**确定；缺原文明确报错。
- `--dry-run` 禁止网络并写 `dry_run.json`；`--max-sends` 在 `requests.post` 发送边界计数，
  超限抛 `SendBudgetExceeded`（已发出/超时照计数）。
- 两阶段：阶段 A 用冻结问题复现 1 轮修复；阶段 B 复用 `_commit_step01_outputs` 做完整审计
  与隔离提交；提交点内部修复轮 = `min(repair_rounds-1, audit_rounds-1)`。
- 输出：`replay_report.json`（输入身份、阶段、发送明细、修复诊断、提交摘要）。

**用例**：`tests/step01_script_gen/test_replay_fixed_input.py`（5 passed）——dry-run 不联网、
缺原文、摘要不符、生产输出根拒写、发送上限边界。

**未覆盖**：合法成功、首轮非法次轮合法、中间补帧、目标未解决、局部回退、预算耗尽
六类桩矩阵（需要更完整的修复服务桩）；缓存分支的端到端集成用例也未新增。
