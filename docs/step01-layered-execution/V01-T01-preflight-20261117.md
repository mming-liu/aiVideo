## 5. S01 收尾（2026-11-17 21:2x，用户复核后）

### 5.1 撤回：`VIDEO_MODEL` 分叉推断不成立

`active_video_model()`（`shared/model_caps.py:200`）**不读**通用 `VIDEO_MODEL`，
只按 provider + `VIDEO_REFERENCE_MODE` 取 `VOLCENGINE_T2V_MODEL` / `VOLCENGINE_I2V_MODEL`
等分渠道变量。独立进程设 `VIDEO_MODEL` 后模型解析不变 ⇒ 本文档上一版"设 `VIDEO_MODEL`
会让能力查询与请求分家"缺少代码依据，已撤回。

### 5.2 `requirements.audio_policy="native"` 的来源（已定位）

调用链：

```
build_frozen_for_shot()
  → generation_requirements()          (step02_video_gen/submit_poll.py:415)
  → active_video_uses_native_voice()   (shared/model_caps.py:486，按 provider 分类)
  → 读取 MERGE_AUDIO_MODE
  → requirements.audio_policy
```

- `active_video_uses_native_voice()` 只看 provider：`volcengine` → `True`；
- `.env.content` 显式 `MERGE_AUDIO_MODE=native`；
- 于是**无声模型** `doubao-seedance-1-0-pro-250528` 的冻结记录里也写了
  `{"audio_policy": "native"}`，而执行声音合同（`execution_requirements._audio_facts`）
  存的是 `native_voice=false / tts_required=true / effective_merge_mode=tts_mix`。

**影响**：`requirements` 整体进 `request_key`（`request_plan.key_facts()` 第 100 行），
所以"payload 一字未变、只切 `MERGE_AUDIO_MODE`"也会让视频缓存 key 失效。Step03/04
仍按解析后的合同消费，不受该字段影响。

**已修（S02）**：`generation_requirements()` 的判据改为
`provider 级原生发声 且 模型级确实有声`（`active_video_supports_audio()`）。
无声模型返回 `{}`，key 不再随 `MERGE_AUDIO_MODE` 抖动；有声模型行为不变。
证据：`tests/step02_video_gen/test_generation_requirements_audio.py`（4 条，含
"key 在无声模型下相同 / 有声模型下不同"的直接断言）。
