## 2. 关键设计说明

### 2.1 G1 的「独立关闭依据」为什么是这三类

复核反例的链条是：**缺证据问题 → 模型改了点名字段 → 修复轮验收通过（触达兜底）→ 身份进入
`_audit_attempted` → 下轮审计沉默 → 旧 G1 豁免**。这条链上没有任何一步证明「问题真的消失了」，
所以尝试记录不能再当依据。

保留的三类依据都能由代码独立复核：

- **(a) 证据消失**：`_audit_issue_resolved` 对「改前在稿、改后不在」的转变有区分度；
- **(b) 确定性检查转干净**：同一 `(镜头, family)` 的确定性质量门条目上一轮报出、本轮不再报出，
  且两轮 `checker_failed` 都为假——这是「同一问题换了一个确定性判据复核通过」；
- **(c) 结构化实体消失**：问题自己声明的 `entity_id` 在修复前目标 `frame_layouts` 里存在、
  修复后消失。这是内容事实，不是「模型动过手」。

配对/跨字段问题（证据按设计必须留在上游字段）由 (b) 或 (c) 关闭；两类都不成立时，
G1 按「缺确定性关闭依据」拒收——这是复核要求的方向，不再用沉默换通过。

### 2.2 预算显式配置的语义

| 配置 | 结果 |
|---|---|
| `TOTAL` 未设置、章目录有账本 | 自动绑定（`ledger_autodiscovered`） |
| `TOTAL` 为整数 `0` | 显式关闭（唯一合法关法） |
| `TOTAL` 为整数 `>0` | 按该上限启用（与账本 `limit` 不一致仍拒收） |
| `TOTAL` 非整数 / 负数 | **配置错误**（fail-closed），不再当成关闭 |
| 只给 `FILE`、文件不存在 | **配置错误**（fail-closed），不再当成未启用 |

只读预检 `describe()` 与发送门禁 `acquire()` 共用 `_validate_ledger`，同一份身份校验。
