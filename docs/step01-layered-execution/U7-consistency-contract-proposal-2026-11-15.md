# Step01 一致性契约层方案（通用修法，非逐镜打补丁）

- 日期：2026-11-15
- 针对：chapter_001 正式稿（revision `0afa8074…`）核出的问题——无声段 56%、旁白落地标点漂移、船宽漂移、酒壶/刃轨迹断裂、shot13 方向语义、camera_movement 语义混用、FF/KF 时序泄漏。
- 原则：**不修"这 13 镜的文本"，修"产生这些文本的契约"**。每条机制消灭一类缺陷的结构成因，且对存量稿可零成本（零 revision 重签）接入。

## 0. 病根诊断（为什么补丁不可接受）

五类问题共同的结构成因只有一个：**约束停留在提示词层，没有落到数据结构层**。

| 缺陷类 | 现状 | 结构成因 |
|---|---|---|
| 旁白标点漂移 | `narration_lines` 已逐字锁定，但落地 diff **只有提示词约定**（audit.py:283 是给模型的规则，不是代码校验） | 无 `segment ↔ lines[k]` 逐字 diff 门 |
| 实体状态断裂（船宽/酒壶/刃） | 有章级静态事实（fact_split/alias_map/character_bank），**没有随时间演进的状态** | 无逐镜状态转移账本；「离手→复得」无人查 |
| camera_movement 语义混用 | outline.py 中 grep 该字段 **0 条值域定义**；13 镜出现 6 种写法含景别 | 无字段值域 schema |
| FF/KF 时序泄漏 | FF_RESULT_LEAK / KF_FUTURE_STATE 检测器存在，但只在**事后报 advisory** | 检测前移缺位：组装时不给模型时序窗约束 |
| 无声段 56% | 声音计划只有 narration/dialogue 两类；无声是**默认**而非决策 | 无 sound_design 层，「静默」未被显式声明 |

补丁（改 shot 3 的逗号、统一 1.4）只消灭实例；契约修复让**下一章同类缺陷无法产生**、当前章缺陷**机器可发现**。

## 1. 五条通用机制

### M1 旁白逐字门（Landing Diff Gate）
- `narration_segment` 去 `旁白：` 前缀后必须与 `narration_lines[k].text` **逐字一致**；
- 跨镜分句：切点必须落在**原文已有标点**处；原文无逗号则落地不得出现逗号（shot 3 `宝钞的，` 即此类违规）；
- 跨章衔接句（N2「也不会…」承接上文）允许整条不完整，但**逐字不允许变**；
- 实现：确定性函数 `shared/narration_gate.py`，进 script_preflight（C8）。零模型调用。

### M2 实体状态账本（Entity State Ledger）
- 章级新数据结构 `entity_state`：`{entity, attr, value, since_shot, final_state}`，只登记**可变约束**——载具尺寸、人物持有物、位置朝向、伤势/衣着状态；
- 规则（全部确定性可校验）：
  1. **尺寸唯一**：同一实体同一度量全章一个值（船宽 1.3 vs 1.4 直接报）；
  2. **状态连续**：本镜 ff 初态 = 上一镜 lf 登记终态；「离手→复得」必须存在中间「取回」动作镜（酒壶 shot6→shot7 即此类）；
  3. **转移有据**：lf 里的新状态必须能在 motion_desc 中找到成因（刃「没入心口」→下镜「反握带血短刃」缺拔刃动作即此类）；
- 关键设计：**账本不改稿件文本，只约束下游**——02a/02b 组装时消费账本，把「船宽 1.4m、可容 3 人」作为视觉约束注入参考图/视频 prompt。已出图帧不受影响，未出图镜头自动获得一致约束。

### M3 字段值域 schema（Field Domain Schema）
- `camera_movement` 枚举：`固定机位 | 推近 | 拉远 | 环绕 | 摇镜 | 跟随 | 手持 | 复合:<主>+<副>`；
- 景别独立成 `shot_size`：`远景 | 全景 | 中景 | 近景 | 特写`；
- outline schema 补字段定义（当前 0 条）+ script_preflight 值域检查（C9）；
- 「环绕镜/环绕」别名在 alias_map 归一。

### M4 时序因果窗（Temporal Causality Window）
- 组装时向模型提供显式时序契约：`ff ∈ [0, t1) ⊆ motion 窗`、`kf_t ∈ (t1, t2)`、`lf ∈ (t2, T]` 且 **lf 动作必须被 motion 覆盖**；
- 现有 FF_RESULT_LEAK / KF_FUTURE_STATE 检测器保留为回归门，但缺陷源头在组装期被契约消除——检测从「事后报警」变「事后兜底」。

### M5 声音层完备性（Sound Design Layer）
- 章级新增 `sound_design`：每镜显式声明 `audio: 旁白k | 台词k | sfx:<描述> | bgm:<氛围> | silent_by_design`；
- Step03 audio plan 泛化为四类音轨（narration/dialogue/sfx/bgm）；
- Step04 门禁新增覆盖率报告：**静默必须显式声明**，`silent_by_design` 未声明的无声镜 → advisory；
- 这是「默认无声 → 显式决策」的结构反转，无声段问题从此变成一个看得见、可审批的产品决策。

## 2. 三层落地（核心：与 revision 重签解耦）

| 层 | 内容 | 触发重签？ | 时机 |
|---|---|---|---|
| **L0 检测器先行** | M1 逐字门 + M3 值域检查落进 script_preflight，对当前稿**只报 advisory** | 否（rule fingerprint 变更走既有零调用 refresh-gate 流程，判定不变） | 立即可做 |
| **L1 账本约束下游** | M2 账本登记当前稿事实值（船宽=1.4 等）+ M5 sound_design 登记（含箫声 sfx、静默镜声明）；02a/02b 组装消费账本 | **否**（不碰 script_result.json 采纳文本） | U7 第 1 批授权**前**决策 |
| **L2 新稿契约** | M1–M5 全量进 Step01 生成管线（outline schema + 组装 + preflight 阻断级） | 是，但只影响**下一章**新稿 | chapter_002 起生效 |

L0/L1 的本质：**存量稿不重签、已出图帧不失效，连续性与声音完备性照样被修复**。之前「改稿 vs 带病进 U7」的二难被解除——因为修的不再是稿，而是稿下游的约束层。

## 3. 已知约束与风险

- L1 注入帧 prompt 走全局前缀通道（类似 style_prefix）：**动 style_prefix.py 会变更 RULE_SOURCE_FINGERPRINT**（R6 曾因此回退）——L1 实现须避开 style_prefix 文件本身，用独立注入模块 + 独立指纹登记，或排入 R7 窗口；
- M2 账本的「事实值登记」需要一次人工确认（1.4 还是 1.3：以 shot 3 起多数值 1.4 为默认建议）——这是**一次性数据决策**，不是每次都要做；
- M5 的 sfx/bgm 生成通道尚不存在（Step03 目前只有 TTS）：L1 只做「登记与声明」，真实音频生成排 U8+ 单独立项；
- 检测器新增会放大 advisory 数量（当前 83 条），门禁阈值不需调整（advisory 本就不阻断）。

## 4. 建议的执行顺序

1. **立即**：L0——`shared/narration_gate.py` + camera_movement/shot_size 值域检查 + refresh-gate 零调用重签；当前稿将机器化地暴露：shot 3 逗号漂移、shot 7/12 景别混用、shot 13 复合运镜未声明；
2. **U7 第 1 批授权前**：出 L1 账本初版（entity_state + sound_design 两个 JSON）供人工确认事实值，批准后 02a/02b 接线；
3. **chapter_002 立项时**：L2 全量契约进 outline schema 与组装链。

每一步都是独立可交付、可回滚的小步，不依赖一次性大改。

## 5. 三份 prompt 的调整清单（L2 证据核查结果，2026-11-15）

## 6. 原文 ↔ 大纲产物独立比对（2026-11-15，程序化逐字核对）

样本：原文第001章（5052 字，`锦衣夜行_77119小说.txt` 行 5–121）vs `script_result.json` 全链。**总体逐字保真度高**，但发现 4 个规划层真缺陷：

|---|---|---|---|
| 1 | **N2 因果分句「若非如此」无承载落点**。原文：「……服侍人的本领更是了得，**若非如此**，前几日往泰州府去时，杨公子也不会花了两百贯宝钞的高价把她买下」——产物全文「若非如此」仅在 `plan_verification` 证据引用中出现 1 次，**不在任何镜头承载链上**。N2 语义悬空的真正根因（比 shot 3 逗号漂移更深一层） | 产物旁白承载：shot2=N1、shot3=N2，无任何镜承载「若非如此」 | 规划层缺陷：旁白分句只登记句子后半段，前半段既没落到前镜也没声明省略 |

**通过项**（保真度证据）：旁白 4/4 逐字命中、台词 1/1 逐字命中且说话人归属正确（张十三）、地名 4/4 全部真实（云河镇×3/照月湾/泰州府/青州×6）、略表 5 项全部能在原文定位且声明合规、时间预算（70–80s）与实际（76.75s）吻合、climax/causal_chain 与原文情节序一致。

**对方案的修订**：
- M1 检测器扩展为两条：① 落地 diff（已设计）；② **分句承载完整性**——原句被拆分承载时，每个分句必须落到某镜或显式声明省略，「若非如此」类无声丢失直接报；
- M2 新增「候选物→账本」消费链：`prop_state_candidates` 的登记必须被分镜消费或显式否决（酒囊类漂移在采纳前拦截）；
- 证据连续性检查（事实 evidence span 不得跨「……」拼接）纳入 L0 检测器清单。

## 7. Prompt 长度与规则密度实测（2026-11-15）——「规则失效是不是 prompt 太长」

### 7.1 实测数据

| Prompt | 长度 | 硬规则词（不得/必须/禁止/不许/只可/只能） | 密度 |
|---|---|---|---|
| 大纲 OUTLINE_PROMPT | 6,460 字 | 39 处 | **每 165 字 1 条** |
| 大纲修复指令（delta/ops/view 三段） | 4,500+3,666+3,215 字 | 20+23+14 处 | 同量级 |
| 正文 SYSTEM_PROMPT | 6,488 字 | 36 处 | 每 180 字 1 条 |
| 正文 DOUBAO_SYSTEM_PROMPT | **14,821 字** | 55 处 | 每 270 字 1 条 |
| 正文 PROMPT_TEMPLATE + 词库 | 8,082+3,900 字 | 33+0 处 | 组装后总量 **20k–27k 字** |
| 审计 audit.py | **58,670 字** | 82 处 | 最重，但有 plan_verification 结构化通道分担 |
| 修复 regen_feedback（实测组装） | **3,041 字** | **5 处** | 太薄 |

### 7.2 结论：长度是次要因素，结构才是主因

- **绝对长度不算失控**：大纲 6.5k 字 ≈ 5k token，远小于上下文窗口；「太长」不成立。
- **真正的压力是规则密度与无分层**：大纲每 165 字 1 条硬规则，正文组装后 20k+ 字、100+ 条规则**平铺无优先级**——指令遵循随「同时生效的约束数量」下降，且后位规则（85% 处）天然弱于 schema 位（12%）。
- **决定成败的变量是「有没有代码门」，不是长短**：
  | 规则 | 位置 | 代码门 | 结果 |
  |---|---|---|---|
  | 旁白逐字 | schema 字段名「逐字照抄」（12%） | ✓ 前置确定性门 | ✓ 生效 |
  | 连续原文 | 18% 处一次性陈述 | ✗ | ✗ 失败 |
  | 分句承载 | 85% 尾部 | ✗ | ✗ 失败 |
  | 运镜值域 | **根本没写**（v6.43 误删） | ✗ | ✗ 失败 |

### 7.3 三份 prompt 的问题各不同向

1. **正文：同病更重**——20k+ 字、100+ 规则平铺；`SYSTEM_PROMPT` 与 `DOUBAO_SYSTEM_PROMPT`（14.8k 字/55 规则）两套并存疑似冗余；旁白落点规则埋在组装序列 73–78% 处。
2. **修复：反向问题——太薄**——3k 字 5 条规则，关键锁定条款（旁白逐字、状态对称）缺失，与 5.3 节发现一致。
3. **审计：最重但结构化分担**——58k 字靠 `content_verification.v4` 的结构化字段兜住大半，漏掉的恰是**没有对应结构化字段**的「连续原文」（evidence_spans 只判 supported，无连续性校验）。

### 7.4 对策：规则预算三层制（并入 L2 设计）

- **硬规则退役出 prompt**：值域类改 schema 枚举（模型只能选合法值），逐字/承载/连续类改代码门（生成后校验）——prompt 只留一行提醒+一个正反例，不再靠模型记忆 39 条「不得」；

- **修复增重**：按 5.3 补锁定条款（预计 +600 字）——修复 prompt 是唯一需要「变长」的。
