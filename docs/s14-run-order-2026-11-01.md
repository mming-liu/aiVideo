### 3.1 上限如何被保证（发送前拦截）

- 所有生成 POST（含 `InputTextSensitiveContentDetected` 改写后的第二次 POST）都经过同一个 `_send()`：**先查上限、再发请求**；
- `VOLCENGINE_IMAGE_MAX_ATTEMPTS`：单次 `generate()` 的尝试次数（运行单设 1）；
- `VOLCENGINE_IMAGE_MAX_POSTS`：进程级整批预算（运行单设 6），跨资产/帧累计；
- `VOLCENGINE_IMAGE_FAIL_FAST=1`：任一次失败后，后续 `generate()` 在发送前被拒；
- `STEP02A_FAIL_FAST=1`：肖像批次首个视角失败即中止，不再请求后续视角，也就不会进入帧阶段；
- 失败出口统一：**输出敏感软跳过（soft_skip）与下载失败**同样记中止标记，不只普通失败；
- 离线用例覆盖：上限 1 + 输入敏感 → 恰好 1 次 POST；输出敏感软跳过 / 下载失败 / 首次 5xx 后再次 generate → 0 次追加 POST；批次入口首视角失败（含 SOFT-SKIP）→ 仅 1 次调用，不再进入帧阶段。

### 3.2 视觉 QC 与自动修图（**不计入图片 POST 预算**）

- 视觉 QC 默认开启（`IMAGE_QC_ENABLED=1`），每次 QC 是一次**视觉模型调用**，不经过图片 `_send()` 预算；S14 默认关闭：`IMAGE_QC_ENABLED=0`（如要开启，须单独列入调用授权）。
- 修图**默认关闭**（`IMAGE_QC_REPAIR_ENABLED` 默认 0；`QC_MAX_ATTEMPTS<=1` 时也强制关闭）：QC critical 后不发起 i2i 修复/doodle 二修，避免挤占 6 次图片预算。运行单仍显式设 `STEP02A_NO_REPAIR=1` 作为双保险。
- `step02a --plan-only` 不写任何文件（console logger + 不落 `step02a_prompt_quality.json`），并输出完整 `writes` 清单。
- `step02a` 成品验收为 BLOCK（缺帧/不可解码）时默认 `exit 1`。
- 因此“6 张”指图片生成 POST；QC 调用与修图各自独立记账。
