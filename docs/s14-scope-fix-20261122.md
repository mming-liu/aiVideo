## 二、第 2 步：ch1 legacy 拆分裁决校准（判定为**来源缺陷**，不放宽门禁）

现场：`.tmp/s14/exec/cmp_ch1_vsplit.json`（父 f10、子 f10.1/f10.2、M 原始回答与事务结果）；原文第 1 章。

- 原文实际两句：张十三先对庄仆说「**公子爷吃醉了酒，险些跌落水中，所以惊得听香姑娘尖叫起来。**」；
  随后又说「且慢……有些**生意上的事情急需公子爷赶回去处理**……我和听香姑娘要扶公子马上回城。」
- 父主张：「张十三对庄仆谎称公子醉酒，并称有生意急事要回城」——含两个分句，「要回城」**缺主体**；
  它的 evidence 只引了醉酒那一句，**不覆盖**「生意急事要回城」。
- 子主张：f10.1 = 醉酒落水→惊叫（与原文一致，细节来自父证据）；f10.2 = 生意急事需公子回城处理（与原文一致）。
- M 判 `partial` 的理由：把父主张的「要回城」按字面读成**张十三本人**，子改成公子 ⇒ 主体变了。
- 判定：**父主张在来源处有缺陷**（复合主张 + 证据只覆盖一半 + 缺主体），不是 M 判据误拒，
  也不是子主张新增了父主张没有的因果。因此：不放宽 M 门禁、不修子主张、不为这次失败重跑。
- 佐证：冻结计划过影子入口 `plan_preflight`（`fact_atomicity`）→ f10 报
  `fact_atomicity_composite_uncovered`，两个分句都无连续证据直接覆盖
  （`.tmp/s14/exec/ch1_atomicity.json`）。影子入口明确「不接生产主门」；初始大纲 prompt 已写明
  「一条事实只写一件事 / 证据必须覆盖全部内容 / 跨两段原文各自另立一条」（`outline.py:90-97,114-116`），
  本次是**模型未遵从**，不是规则缺口。
- 处置建议：来源修正是让首版规划把这类事实拆成「一句一条、各自连续证据」；影子原子性检查若要使用，
  应先接**计划修订反馈**（不是硬门）并单独校准。本轮不动正式门禁，ch1 legacy 继续停在计划层。

## 六、合并补记（2026-11-22，与 `codex/lightweight-voice-repair` 合并）

本节取代第一节的修订机制；第二、三节的取证读数保留为历史记录。

- 同一功能有两套并行实现：本文第一节「第二次请求重答整份大纲 + 代码逐项比对范围」，与
  `lightweight_voice_repair.py`「模型只回 `edits`（id + 新 text），代码基于原稿应用」。两者改同一循环，
  合并时保留 **edits 协议**（用户 2026-11-22 指定的“基于原稿的定点局部修正”）；`revision_scope` /
  `_revision_block` / `_revision_scope_problems` 等整稿重答路径随之移除，范围守卫由协议结构本身承担
  （未点名字段模型无法提交）。
- 保留并复用本文第一节的 `plan_feasibility.voice_entry_representability`（单镜判据唯一入口）与
  `budget_band` 同源上限；`res["revision"]["scope"]` 继续取 `replace` / `trim`（无需修订时为 `none`）。
- 现行行为：大纲 prompt 写明全章声音 ≤ 10 条、≤ 280 汉字、单条 ≤ 42 汉字、目标 55–80s；超限后最多 2 轮
  edits 修正，均基于同一原稿。`replace`（≤ 90s、个别句超单镜）只开放超限句，候选为原文同段逐字、≤ 11s；
  `trim`（> 90s 或条数/字数超限）发回逐条 id/字数/估时/文本，只能删无事实引用的句或换更短原文句，
  代码复算总时长，不降或未达 `当前 − 80s` 即拒收；整稿回答一律拒收，原稿保留。
- 第一节测试（cff77a7）里的匿名情节（同引语替换、trim 保留必保留声音）已改写为 edits 协议用例。
