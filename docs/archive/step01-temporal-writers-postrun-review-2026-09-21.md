### 问题 A：定向修复轮的「整批全有或全无」（发现 10）——决定 A1

**现象（实测）**

```text
22:21:22 [REPAIR] 替换被拒 1 条: ["目标集合不完整：缺少 ['16']（本轮点名 ['16', '4', 'hook']）"]
```

模型回了镜头 4 与 hook 的替换、漏了镜头 16 → **整批回滚**，`applied=0`。而镜头 4 与
hook 的替换**本身合法且已通过授权校验**，一并作废。

**根因**：`_apply_shot_replacements()`（`main.py:2034-2046`）先构造 `expected_targets`，
逐个比对 `got`，缺项/越界都 append 到 `rejected`，随后 `if rejected: return script, 0, rejected`
——原脚本一字不动。这条是**二次审核发现 4** 明确要求的安全保证，故未自行改动。

**为什么在当前形态下是纯损失**：`expected_targets` 防的是「只提交一部分却当整批成功」，
那是**报告失真**，不是**数据损坏**。而数据侧的安全保证**全部是单镜作用域**：

| 保证 | 作用域 |
|---|---|
| `check_replacement_authorized`（字段授权） | **单镜** |
| `canonical_path_diff`（越权路径检测） | **单镜** |
| `_final_field_mask_violations`（锁定字段） | **单镜** |
| 逐镜 revision gate | **单镜** |
| 每镜时间不变量 | **单镜** |

replacement 是「**完整镜头对象**」，写入的每个字段都属于该镜头自己——**不存在任何跨镜字段**。
所以「只有跟别镜一起改才成立」的情况不存在，逐目标提交不削弱上表任何一条。

| 选项 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A1 逐目标提交**（建议） | 合法且授权的目标立即生效；缺项/越权目标**单独**拒绝并如实记录 `applied/rejected` | 无额外模型调用 | 要改 `_apply_shot_replacements` 的提交语义 + 补「部分提交」回归；需确认逐镜 revision gate 仍逐镜跑 |
| A2 保持整批原子 | 不动 | 修复轮可能长期 0 产出（本轮即 0） | 发现 8 刚接上的 `kf_event_window_mismatch` 路径会**永远得不到真实验证** |
| A3 折中：缺项重取一次 | 缺项 ≤1 且其余全通过时，只重取缺失目标再整批提交；缺项 ≥2 仍整批回滚 | 多 1 次模型调用 | 不推翻原子性语义，但把「模型漏项」转成额外开销而非修复收益 |

**决定采用 A1，但不是无条件部分写入。**实施边界如下：

1. 原子性下沉到**单目标**：一个完整镜头要么全部通过并暂存，要么该目标完全不动；
2. 缺失、重复、越界、未授权或结构不合法的目标分别记入 `rejected`，不得计作 resolved；
3. 合法目标形成一个 staged subset，在脚本副本上一次应用；
4. 应用后继续运行整份脚本的接受判定：不得新增 blocking、不得改变未提交目标的
   revision、不得造成完整性退化；失败则回滚整个 staged subset；
5. 跨镜问题若只返回一侧，只有在全局复检证明该子集确实解决问题且没有制造新冲突时
   才能接受。检测器无法证明改善时按保守策略回滚。

因此改变的是“模型响应必须覆盖全部点名目标”这一**传输完整性**要求；字段授权、逐镜
事务、非目标 revision 和全局质量门均保留。A3 会为模型漏项额外付费，当前没有必要。

### 问题 B：时长收敛（发现 11）——决定 B1+B2，预算暂不增加

```text
22:15:48 [DURATION] 正片 103.0s > 90s，反馈 LLM 精简/合并到 70-80s（尝试 1/1）...
```

最终正片**实际** 93.3s，`duration_budget` 一条留到质量门；落盘脚本的**投影**是 111.38s。

**B-1 判定口径：触发量的是「不会发生的未来」**

| 环节 | 量的东西 | 本轮数值 |
|---|---|---|
| `_regen_over_limit` 的 `duration_over` | `project_post_split_metrics()` 的**拆镜后投影** | 触发时 103.0s |
| 质量门 `duration_budget` | **实际** `Σduration_sec` | 93.3s |

投影会把超过 cap 的镜头按 cap 折算并**计入拆镜次数**，但拆镜 pre-pass 在生产路径
**已停用**（`timecode.py:695` 的 `allow_split=False`）——投影描述的是一个**不会发生的剧本**。
于是触发阈值与验收阈值不是同一个量：投影 < 90 而实际 > 90 时**该收敛的不触发**；
投影 ≫ 实际时**反复重生成**，且要求模型压的是投影而不是门禁量的那个数。

**B-2 这条路径没有任何采纳守卫，预算只有 1 次**

```python
try:
    new_script = parse_response(raw, novel_text=novel_text)
except ...:
    break
script = new_script        # ← 解析成功即无条件替换，无质量判据
```

对比：候选选择有 `_candidate_sort_key` 排序，结构轮有采纳判据（发现 7 刚修好），
而时长轮**解析成功就用**——一次坏重生成不会被拒。且本轮 `max_attempts =
GAP_MAX_REGEN_ATTEMPTS = 1`；又因 `SHOT_COUNT_MAX <= 0`（当前配置）使 `over_max`
恒为 False，**连强制截断兜底也被跳过**。结果：**时长维度零兜底**，超了就一直超到质量门。

| 选项 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **B1 只修口径**（建议先做） | `duration_over` 改用实际 `Σduration_sec`；投影口径只保留给候选打分 | 无额外调用 | 触发次数可能上升（实际 > 90 的稿子会开始触发收敛） |
| **B2 口径 + 守卫**（建议一并做） | 在 B1 基础上加采纳守卫：不得比原稿更差（判据同结构轮：实际时长不得变差、不得引入完整性异常） | 无额外调用 | 需定「更差」的量法；守卫判据本身要写回归 |
| **B3 口径 + 守卫 + 提预算** | 再把 `max_attempts` 提到 2–3（与 `GAP_MAX_REGEN_ATTEMPTS` 解耦） | 每次多 1–2 次全脚本生成 | 成本明确上升，属真正的花费决策 |
| B4 暂不改 | 记录在案 | 无 | 93.3s 只超 3.3s；先看发现 13 的提示词容量自检能否把镜头数/时长一起带进区间 |

**决定实施 B1+B2：**

1. 收敛触发、循环继续条件和成功判定统一使用最终对象的实际
   `sum(shots[*].duration_sec)`；
2. `project_post_split_metrics()` 只用于诊断和候选排序，禁止再控制生产收敛，因为
   `allow_split=False` 时该投影不会成为真实时间轴；
3. 新稿只有在 `max(0, actual_total - 90)` **严格下降**时才具备采纳资格；
4. 同时要求结构非法镜头数不增加、`integrity_ok is not False`，并复用已有退化检查，
   防止靠删剧情、破坏原文锚定或把长台词重新塞进单镜来换取总时长下降；
5. 本轮不采用 B3，`max_attempts` 保持 1。下一次真实运行记录“触发前实际时长 / 新稿
   实际时长 / 守卫拒绝原因”；若提示词容量自检已生效但仍经常停在 90–95s，再单独决定
   是否把**时长收敛专用预算**提高到 2，不能继续借用 GAP 预算。

1. 原文连续切片 / 台词归属；
2. 每镜主体、地点、核心事件；
3. 估算时长与单镜 3.5–8s 约束；
4. 全片 60–90s 与镜头数约束。

shot-plan 通过后，才按 plan 中每个镜头分别生成 prompt、FF/LF、KF 和 layout。
