## 为什么

1. **200 字是摘要的容量，不是选材的容量**：摘要装不下"7 句台词 + 事实 + 事件顺序"（实测第 1 章
   【本章主要事件】一行 178 字、【必须保留事实】309 字、【镜头节拍】332 字），所以选材必须走
   另一条**不压缩**的通道。抬高 `max_chars` 会把完整大纲塞回摘要、重新引入它当初要避免的问题。
2. **为什么摘要不再带台词**：用户指出"前 2 句虽标注诚实，仍不能约束模型执行全部 7 句"。既然完整
   集合由契约块负责，摘要里的残缺清单只会挤掉摘要自身的内容——改后同章摘要是
   **199 字：情绪弧线 / 结尾钩子 / 出场角色 / 因果链 / 高潮**（改动前只剩 **26 字**：仅高潮）。
3. **下界不等于欠时**：`lower_bound = max(对白估时, 节拍下限)` 是"至少这么多"。54.74s < 60s 只能
   说明"下界没到下限"，对白与画面动作可同时发生，成片是否达到 60s 必须看生成稿实际时长——
   原来的文案把下界当成了欠时证据。
4. **"一次"必须绑定计划版本**：否则缓存里那份"重选后仍超限"的计划会让**每一轮运行**都再烧一次
   模型（每次调用一次），这既不是用户要的语义，也永远收敛不了。

## 影响面

- **提示变化（仅提示）**：四个完整稿生成入口的 user prompt 末尾新增契约块（真实数据 **890 字符**：
  7 句台词 + 5 条必保留事实 + 5 条事件顺序）。压缩摘要内容变化（见上）。无判据/容量/修复轮改动。
- **重选调用次数下降**：同一计划版本最多一次；缓存命中且结论为"仍超限"时**0 次**模型调用。
- **低于下限的文案不再给"补内容"的动作指令**（避免在规划层对总时长下结论）。
